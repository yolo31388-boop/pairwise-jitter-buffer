# pairwise-jitter-buffer

实时通话的用户投诉声音一会儿快一会儿慢，丢包时直接卡住半秒，而且切到后台再回来音画就对不上。查下来是 rtc/jitter_buffer.py 的抖动缓冲有严重问题：update_depth() 缓冲深度写死成最小值，网络抖动变大也不加深；push() 按到达顺序堆包，乱序到达的包不按 seq 重排，重复包照样入队，迟到的包也不丢弃；drain() 完全不看播放截止时间，包到齐就立刻吐出去，缓冲深度形同虚设；丢包时不做 PLC，直接跳过，听感上就是一段空白；重传包（NACK）被当成新包追加到队尾，播放顺序更乱；FEC 包被当成媒体包播出去；容量满了不淘汰，内存一直涨；flush 只清数组，计数器不清零。你要修的是：缓冲深度随抖动自适应升降并限幅；入队按 seq 排序、去重、丢弃迟到包；按截止时间出队，缺口生成 PLC 事件；重传包插到正确位置；FEC 只计数不播放；容量满淘汰最低序号；flush 重置全部状态；统计丢包率。rtc/jitter_buffer.py 是核心，tests/test_jitter_buffer.py 15个红。

## 运行

```
python -m pytest tests -q
```

初始状态：15 个用例失败。修复实现使全部用例通过，不要修改 `tests/` 下的测试。
